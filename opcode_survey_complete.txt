## COMPLETE FIXED MAP FOR COQ MODEL:

The Coq model currently uses byte INDICES directly as opcode discriminants, which is INCORRECT.
Instead, we need to use the ACTUAL Rust enum discriminant values.

However, looking at the Coq structure more carefully:

Current Coq defines: `Definition opcode_price_all : Z → Z := match op with | 0 => 1 | ...`

This maps INDEX→PRICE, where index should equal the bytecode value.

But the problem is the COQ EXAMPLES are using WRONG indices for named opcodes.

For example:
- Coq says: "NOP (0x21)=2" but then defines opcode_price_all 32 = 2
- Should be: opcode_price_all 33 = 2 (since 0x21 = 33)

The TABLE ITSELF in Coq looks mostly correct (matches OPCODE_PRICE_TABLE array),
but the EXAMPLE NAMES don't match their indices!

## FINAL DIAGNOSIS:

The Coq file has TWO bugs:
1. Example comments say "NOP" but bind index 32 instead of 33
2. Example comments say "ADD" but bind index 159 instead of 158
3. Many other examples have similar issues

The SOLUTION is to update the example bindings to use correct indices based on the survey.
