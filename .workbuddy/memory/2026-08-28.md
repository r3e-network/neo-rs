## Neo N3 协议合规系统性审计（v3.9.1）

对 neo-rs（1165 文件 / 254k 行）做了 6 域并行审计 + 关键结论回源验证。
完整报告：`docs/audits/2026-08-28-protocol-compliance-audit.md`

### 方法要点（可复用）
- 关键结论**不依赖记忆**，一律抓取 C# 原始源码核对：
  - `raw.githubusercontent.com/neo-project/neo/v3.9.1/src/...`（GitHub API 常被限流，raw 可用）
  - `neo-project/neo-vm` 最高 tag 是 **v3.9.0**（无 v3.9.1）
  - BLS: `Neo.Cryptography.BLS12_381/master/src/Neo.Cryptography.BLS12_381/`
  - dBFT: `neo-modules/master/src/DBFTPlugin/Consensus/ConsensusService.OnMessage.cs`
- 硬分叉高度用**公网节点 `getversion`** 实测验证（seed1.neo.org:10332 / seed1t5.neo.org:20332），比查 config.json 可靠（官方已迁移路径）
- 派子代理审计时必须禁止其运行 cargo（会与后台编译争锁）

### 已修复（10 项 + 2 项测试构建故障）
1. `neo_token/governance.rs:470` `register_internal` 缺无条件 `CheckWitness`（**CRITICAL**，任意注册候选人）
2. `neo-vm/src/vm/limits.rs` `MaxItemSize` 三处取值互相矛盾且全错 → 统一为 `ushort.MaxValue*2 = 131070`；`MaxComparableSize` → 65536
3. `neo-config/src/protocol.rs` 主网/测试网 `hf_faun` 缺失 → 8_800_000 / 12_960_000
4. `crypto_lib/bls12381.rs` 拒绝压缩无穷点 → 按 C# 接受 `0xC0‖0×47`
5. `big_decimal.rs` 解析 `"0.0"`/`"100.0"` 失败（裁零顺序错）
6. `consensus/handlers/commit.rs` off-view Commit 未验签即可占位
7. `consensus/handlers/prepare.rs` 覆盖本地 version/prev_hash → 改为拒；补 MaxTransactionsPerBlock 与时间戳校验
8. `config/mainnet-stateroot.toml` 主网配了 TestNet 端口
9. 补 `UInt160/UInt256::equals(Option<&Self>)`、`MockBlock::size()`（**解锁 neo-primitives/neo-core 测试能力**）

### 关键结论 / 易踩坑
- **NameService(NNS) 不是原生合约**（是部署合约 `0x50ac1c37...`），项目 11 个原生合约清单正确，不要"补"第 12 个
- C# `Hardfork` 枚举是 **0 基**；`CommitteeMembersCount = StandbyCommittee.Count`（不减 1）；`GetRandom` 门禁 Aspidochelone（非 Domovoi）—— 既有文档假设有误，项目实现是对的
- **最高风险待查项 (R1)**：`Prefix_GasPerBlock`/`Prefix_ContractHash` 索引后缀一律大端写，C# 是否同为 BE 未确证；`contract_id_storage_key_legacy`(LE 回退) 暗示曾经踩过坑。若 C# 是 LE 则存在 state root 级分叉

### 环境
- `cargo check --workspace` 在本机失败：`librocksdb-sys` 在 host `x86_64-pc-windows-gnullvm`（LLVM-MinGW）下编译不了 `env_win.cc`（需 MSVC 的 `FILE_ID_INFO`）。**环境问题非代码缺陷**
- 绕法：`cargo check -p <crate>` 排除 `neo-node`（其 `neo-core/full` 引入 rocksdb）

### 测试覆盖结构性风险
`neo-vm` 仅 313 行测试 / 106 个源文件；`neo-p2p`、`neo-storage`、`neo-config` 0 行。VM 是最易静默分叉的组件。
