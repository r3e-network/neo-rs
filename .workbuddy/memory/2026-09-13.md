# 2026-09-13 neo-rs 性能优化（导入吞吐）

## 用户诉求
用户贴出一份外部瓶颈分析，要求「优化 neo-rs」。分析结论：慢的根因不是 VM/交易执行，
而是 **MPT 状态树跨块零缓存 + Windows 下 14GB RocksDB 随机冷读**（声称占 80%+），
其次 `allow_mmap_reads` 导致 33 亿次软缺页（~10%）、每次 `try_get` 新建快照、
单线程串行。预测引入跨块 LRU 节点缓存 + 关 mmap 可得 6~10x。

## 报告代码断言逐条核验（全部属实）
- `neo-crypto/src/mpt_trie/cache.rs:72` `entries: HashMap::new()`、`:135` `self.entries.clear()`
  —— 每次 `commit()` 后清空，跨块缓存为零。**属实**。
- `neo-core/.../state_store/snapshot.rs:23` `Trie::new(...)` —— 每个 `StateSnapshot` 新建 Trie。
- `neo-core/.../state_store/backend.rs:233` `let snapshot = self.store.snapshot();` —— 每次节点读新建快照。
- `neo-core/src/persistence/providers/rocksdb/provider.rs:291` `set_allow_mmap_reads(true)` —— 属实。
- `Node::try_hash()` 哈希的是 `to_array_without_reference()`（`reference` 不参与哈希）
  → 节点内容寻址，**跨块缓存对共识根无损**，是纯 I/O 优化。
