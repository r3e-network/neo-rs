# Neo-rs 合规核查清单（节点运行口径）

> **日期**：2026-09-19
> **协议基线**：Neo N3 v3.10.1
> **文档定位**：节点运行所涉及的合规/治理口径核查表，与 `docs/SECURITY.md`、`docs/DEPLOYMENT.md` 互补，聚焦"可勾选的核查表"而非威胁模型叙述。
> **诚实声明**：本节将"当前是否满足"与"应满足标准"并列；未满足项如实标注为待整改，不假装全绿。

---

## 0. 总则

- **密钥/凭据纪律是本合规清单的第一优先项**：任何可用密钥必须只从**环境变量**或**密钥服务**（KMS / Vault / HSM 派生）读取，**绝不硬编码**于源码、配置文件、容器镜像、文档或 CI 日志。
- 项目内历史脚本中存在的硬编码凭据/弱加密扫描项，属**仓库基线待清理**（详见 `SECURITY-ACCEPTANCE.md`），与本协议语义验证是两个独立问题，互不混淆。

---

## 1. 密钥管理

### 1.1 凭据来源（明确要求）

- [ ] RPC 认证（`NEO_RPC_USER`/`NEO_RPC_PASS`）仅从环境变量/密钥服务读取，**不在 `*.toml` 配置中写死明文**（配置可用 `env` 引用或留空由运行时注入）。
- [ ] 共识/出块私钥仅从密钥服务/HSM/受保护密钥文件读取，不在源码或文档出现。
- [ ] TLS 密码（`NEO_RPC_TLS_PASS`）仅运行时注入，不落盘明文。
- [ ] TEE sealing key 材料走受保护路径/环境变量，不在镜像层固化。
- [ ] 仓库扫描确认无可用密钥硬编码（`grep -rn` + Mimosa 扫描封印为证）。

### 1.2 密钥生命周期

- [ ] 生成：OS CSPRNG（`OsRng`），生成后 `Zeroizing` 清零临时内存。
- [ ] 存储：内存 `Zeroizing` / 加密钱包文件（AES-256-GCM）/ HSM / TEE 之一；共识私钥不落明文盘。
- [ ] 轮换：有明确轮换流程与记录；轮换后旧密钥失效率立即生效。
- [ ] 销毁：删除流程覆盖磁盘、备份、日志、CI 缓存。
- [ ] 备份：私钥备份采用分离的受控保险库，且与节点分离。

### 1.3 节点身份

- [ ] 共识节点公私钥对唯一且私钥受控；public key 用于 dBFT validator 注册。
- [ ] P2P 节点身份与 seed/信任名单核对（防地址重定向/伪装）。
- [ ] 密钥失窃预案已定义（见 `INCIDENT-RESPONSE.md`）。

---

## 2. 配置与凭据硬编码核查（可勾选）

- [ ] 所有 `*.toml` 不含明文口令/私钥。
- [ ] 所有 `*.env` 模板使用占位符（如 `<CHANGE_ME>`），不含真实值，且 `.env` 在 `.gitignore`。
- [ ] 容器镜像层不含密钥（`docker history` / 多阶段构建复查）。
- [ ] CI 日志不透出密钥（secret masking 生效）。
- [ ] 文档、示例、测试夹具不含**可用**密钥（测试可含公开的测试向量私钥，但须注明"仅测试"且不对应任何真实资产）。

---

## 3. 备份与恢复

- [ ] RocksDB 数据定期备份（`make backup-rocksdb` / cron），并含**一致性快照**（stop-then-backup 或 live checkpoint）。
- [ ] 备份加密 + 异地/多副本，保留策略明确。
- [ ] 恢复流程已演练（restore 后校验 `getblockcount` / state root 与参考一致）。
- [ ] 恢复的**验证盲区**：存储/MPT 状态一致性（`DEPLOYMENT.md` §3 S6）未完成，恢复后必须与参考网络交叉校验，**不得**单方面判定"链一致"。

---

## 4. 审计日志

- [ ] 启用 JSON 结构化日志 + 轮转（`[logging]` 配置）。
- [ ] 记录：节点启停、配置变更、共识参与/缺席、出块、RPC 认证成败、密钥访问、告警触发。
- [ ] 日志保留策略（≥ 规定天数）与访问控制（仅运维/审计角色可读）。
- [ ] 审计日志与业务日志分离或可过滤，便于取证。
- [ ] 日志中不记录密钥明文/签名私钥材料。

---

## 5. 网络暴露面

- [ ] P2P 端口按需开放（mainnet 10333 / testnet 20333）；firewall 仅放行所需端口。
- [ ] RPC 默认 `bind_address=127.0.0.1`；对外暴露时经反向代理 + TLS + 认证 + 方法过滤 + 限流。
- [ ] CORS 关闭（`cors_enabled=false`）；危险 RPC 方法禁用（`disabled_methods`，如 `openwallet`）。
- [ ] 健康/指标端口（`/metrics`）不对外匿名暴露或已鉴权。
- [ ] 暴露面收口与 `docs/RPC_HARDENING.md` 一致。

---

## 6. 供应链

- [ ] **Cargo.lock 已提交并固定**（仓库根存在 `Cargo.lock`），依赖版本锁死、可复现构建。
- [ ] `cargo-audit` 无已知漏洞（或已评估豁免并记录）。
- [ ] 关键依赖（ring / ed25519-dalek / rocksdb）来源与版本基线登记。
- [ ] **C# runner 仅作验证工具，不随生产部署分发**：`tools/csharp-vm-runner`、`tools/csharp-serialization-runner`、`tools/csharp-app-runner` 及 `external/*` 仅用于差异验证 CI/审计，不属于 `neo-node` 运行时产物；生产镜像只含 Rust 二进制与其运行时依赖。
- [ ] 第三方原生库（如 RocksDB）与 Rust 二进制匹配的版本/ABI 已核对。
- [ ] 外部/引用仓库（`external/`）的引入与许可、来源登记，且不进入运行时构建。

---

## 7. 协议/兼容合规（与形式验证证据挂钩）

- [ ] 参考实现基线固定 **v3.10.1**，差异验证锁该版本（C# runner csproj 注释 "Do NOT float"）。
- [ ] VM 指令语义、wire 序列化、对齐 syscall 子集的差异验证 PASS（见 `DEPLOYMENT.md` G1-G4）。
- [ ] **明确声明未完成项**：存储/原生合约正路径、完整区块状态一致、Coq 9 个未通过模型（`DEPLOYMENT.md` §3）。这些不构成"协议已 100% 合规"的声明基础。
- [ ] 任何协议相关变更上线前，须触发对应差异验证 + Coq 门禁（`formal/ci/check_coq.py --all`）。

---

## 8. 综合合规核查表（勾选交付）

| 类别 | 项 | 当前状态 | 达标标准 |
|------|----|---------|----------|
| 密钥管理 | 凭据仅环境变量/密钥服务，无硬编码可用密钥 | **要求（必须满足）** | 扫描无命中 |
| 密钥管理 | 共识私钥受控/零化/备份分离 | 待演练确认 | 记录在案 |
| 配置 | 无明文口令/私钥于 toml/env/镜像/日志 | **要求** | 扫描无命中 |
| 备份恢复 | 备份+加密+多副本+演练 | 依赖既有流程 | 演练记录 |
| 审计日志 | 结构化+轮转+访问控制 | 部分（需配置确认） | 配置项 |
| 网络 | P2P/RPC 暴露面收口 | 依赖配置 | 配置项 |
| 供应链 | Cargo.lock 固定、无已知漏洞 | Cargo.lock 存在 | `cargo-audit` |
| 供应链 | C# runner 不随生产部署 | **要求（架构约定）** | 镜像清单 |
| 协议 | 差异验证 PASS（G1-G4） | 已证 | 证据产物 |
| 协议 | 存储/原生/状态一致验证 | **未完成（盲区）** | 补齐后声明 |

> 注："当前状态"标注为**要求**的项是本项目必须强制执行的**部署口径**；标注"待演练/待确认/未完成"的项须在授权上线前闭环。

---

**结论**：本项目在**密钥纪律与供应链（Cargo.lock + C# runner 仅验证）** 上有清晰可执行的口径；在**备份恢复演练、审计日志配置确认**上需运维闭环；在**协议语义合规**上，必须如实保留"存储/原生/完整状态一致未验证"这一缺口，不得宣称协议全量合规。
