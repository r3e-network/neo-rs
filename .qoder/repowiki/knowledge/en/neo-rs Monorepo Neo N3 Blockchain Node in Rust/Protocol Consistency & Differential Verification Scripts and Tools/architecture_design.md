The module is split into two scopes with distinct responsibilities:

- `scripts/` — executable harnesses organized by purpose: a large family of `verify-*`, `compare-*`, `find-*-divergence.py`, `download_*`, `reconcile_*`, and `validate-*` scripts that drive the `neo-node` binary (or external C# seeds) via JSON-RPC to compare state roots, block validation, gas, syscalls, P2P, and opcode behavior; orchestration entry points like `mainnet-full-validation.sh` implement a resumable multi-step pipeline (MD5 verify → unzip `.acc` → import → node-start → verify/campaign) with marker files for re-entry; `watchdog.py` monitors a running node's state root height via HTTP and auto-restarts on stalls; `profiling/` contains small `cargo bench --profile-time` wrappers for flamegraph generation.
- `tools/` — compiled binaries used as reference implementations or helpers: `csharp-vm-runner/` is a .NET console app (Neo.VM 3.10.1 pinned in `csharp-vm-runner.csproj`) that executes the same vector JSON produced by Rust harnesses (`gen-vm-diff-vectors.py`, `generate-block-test-vectors.py`) and emits an identical stack envelope so `vm-diff.py` can diff Rust vs C# VM semantics; `sgx-evidence-helper/` is a C++ enclave program built via its own `Makefile` that generates real DCAP quotes and sealing keys for strict `--tee-sgx` mode.

Dependency direction is one-way: scripts invoke the built `neo-node` binary and/or call out to external C# seed RPC endpoints; the two tools are independent executables consumed by scripts but do not depend on them. There is no shared library — each script is self-contained and typically uses only stdlib Python plus `urllib`/`subprocess`.
