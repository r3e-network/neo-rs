Two complementary documentation subsystems coexist under this scope:

- `docs/` is a flat collection of human-readable artifacts organized by purpose: top-level markdown files cover architecture (`ARCHITECTURE.md`, `CLI_ARCHITECTURE.md`), deployment (`DEPLOYMENT.md`, `RELEASE.md`, `mainnet-deployment.md`), security (`SECURITY.md`, `RPC_HARDENING.md`, `tee-fs-acl.md`), operations (`OPERATIONS.md`, `MONITORING.md`, `METRICS.md`), and performance (`perf-report.md`, `performance-baselines.md`, `performance-optimizations.md`). Subdirectories group related outputs: `audits/` holds per-topic audit reports (consensus, transaction validation, smart-contract native, RPC JSON-RPC compliance); `plans/` stores dated implementation plans; `protocol-consistency/reports/` contains thousands of golden-state comparison JSON artifacts produced by automated block-by-block divergence checks against the C# reference node; `archive/state-root/` keeps legacy divergence results; `superpowers/plans` and `superpowers/specs` hold forward-looking design documents.
- `openspec/` implements a spec-driven change workflow. `config.yaml` declares `schema: spec-driven` and optional per-artifact rules. `specs/` holds current living specs (e.g. `protocol-compliance-audit`, `security-hardening`, `configuration-management`) written in an ADDED/Scenario format that pins requirements to exact byte-for-byte compatibility with the C# Neo N3 v3.10.1 reference. `changes/archive/<date>-<slug>/` captures completed change sets, each containing `.openspec.yaml`, `proposal.md`, `design.md`, `tasks.md`, and one or more `specs/<topic>/spec.md` files describing the new or modified specification. The directory structure enforces a strict dependency direction: code changes are gated by spec artifacts in `openspec/`, while `docs/` records the resulting operational and architectural knowledge without importing any code.
