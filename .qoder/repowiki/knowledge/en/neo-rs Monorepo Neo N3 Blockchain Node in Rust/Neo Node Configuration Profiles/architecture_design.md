The module is a flat collection of TOML profile files plus a small `Plugins/RpcServer/` subdirectory containing an example RPC server plugin manifest. Each `.toml` file is a self-contained, production-ready profile targeting a specific deployment surface: `local.toml` (in-memory storage, fast block time, debug logging), `testnet.toml` (RocksDB on testnet ports with seed nodes), `mainnet.toml` (production RocksDB layout with state_service enabled for state-root MPT trie sync), and several specialized variants (`mainnet-full-validation.toml`, `mainnet-protocol-consistency.toml`, `mainnet-stateroot.toml`, `perf-validate.toml`, `tmp-bisect.toml`, `tmp-run.toml`, `tmp-rust5107.toml`) that override network magic, p2p ports, storage paths, consensus flags, and telemetry to support distinct operational or testing workflows. The `Plugins/RpcServer/RpcServer.json.example` provides the shape of per-plugin JSON config consumed by the node's plugin loader. There is no code in this scope — these files are consumed at startup by the node's config loader to populate sections like `[network]`, `[storage]`, `[p2p]`, `[rpc]`, `[consensus]`/`[dbft]`, `[telemetry]`, `[logging]`, `[blockchain]`, `[mempool]`, and `[state_service]`.
