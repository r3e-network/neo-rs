Single Rust crate (`neo-telemetry`) exposing a unified `TelemetryHandle` via `lib.rs`, which orchestrates three subsystems: (1) Logging — `logging.rs` provides basic `tracing-subscriber` initialization; `node_logging.rs` extends it with file output, daemon-mode suppression, and a `LoggingGuard` that keeps non-blocking writers alive. (2) Metrics — `metrics.rs` defines an in-process `Metrics` struct wrapping a `prometheus::Registry` plus a `MetricsServer` facade; `node_metrics.rs` exposes process-wide static `LazyLock<Gauge/Counter>` metrics (block height, mempool, peers, state roots, storage) updated through `update_node_metrics` / `update_timeout_metrics` / `update_storage_metrics` and exported via `gather_prometheus`. (3) Health — `health.rs` defines a pluggable `HealthCheck` registry with `HealthStatus` (Healthy/Degraded/Unhealthy); `node_health.rs` builds a Hyper-based HTTP server on `/healthz`, `/readyz`, `/metrics` driven by a shared `Arc<RwLock<HealthState>>` containing block/header heights, peer count, mempool size, sync flag, plus storage-version verification. A fourth subsystem, `system.rs`, wraps `sysinfo` to expose CPU/memory/disk/uptime as `SystemInfo`. Configuration is centralized in `config.rs` (`TelemetryConfig`, `LoggingConfig`, `LogFormat`, `TelemetryAndLoggingConfig`) with serde defaults, and consumed by two entry points: `init()` for generic use and `init_for_node()` for the node daemon path. Dependency direction is one-way: `lib.rs` re-exports public types from each sub-module; sub-modules depend only on config/error and their own domain crates (hyper, prometheus, tracing, sysinfo), never on each other except `node_health.rs` calling into `node_metrics::gather_prometheus`.
