The crate is a single Rust library (`neo_json`) whose public surface is re-exported from `src/lib.rs`. Core data model lives in three sibling modules: `j_token.rs` defines the `JToken` enum (Null/Boolean/Number/String/Array/Object) plus serde `Serialize`/`Deserialize` via a custom `TokenSeed`/`TokenVisitor` that enforces a configurable max nesting depth; `j_array.rs` wraps a `Vec<Option<JToken>>` to allow sparse arrays with `null` slots; `j_object.rs` wraps an `OrderedDictionary<String, Option<JToken>>` to preserve insertion order. `ordered_dictionary.rs` provides the insertion-order-preserving map backed by `indexmap::IndexMap`, exposing `try_insert` for duplicate-key detection. `error.rs` centralizes all errors as a `thiserror`-derived `JsonError` enum consumed across modules. Querying is split into `j_path_token.rs` (parser + evaluator) and `j_path_token_type.rs` (token type enum), invoked via `JToken::json_path`. Dependency direction is strictly one-way: `j_token` → `j_array`/`j_object`/`ordered_dictionary`; `j_object` → `ordered_dictionary`; path modules depend only on `j_token` and `error`. Tests live under `tests/` as integration tests covering each type and serialization round-trips.
