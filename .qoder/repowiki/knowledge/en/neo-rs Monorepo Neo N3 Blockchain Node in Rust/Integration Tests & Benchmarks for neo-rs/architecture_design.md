Two sibling Cargo packages form this scope. `tests/` is the `neo-tests` crate (publish = false) whose `src/lib.rs` exposes shared test fixtures — a minimal in-memory `mempool` facade, and a `state` module defining `WorldState`, `MemoryWorldState`, `StorageKey`, `StorageItem`, `AccountState`, `StateChanges`, and a deterministic `StateTrieManager` used by all tests. The `tests/tests/*.rs` files are declared as individual `[[test]]` targets in `Cargo.toml` (layer_boundary_tests, consensus_integration_tests, state_integration_tests, end_to_end_tests, chaos_tests, e2e_transaction_flow, p2p_message_exchange, contract_execution, no_local_neo_vm_dependency, fast_sync_p2p_e2e_tests), each importing workspace crates from layers 0–4 (`neo-primitives`, `neo-io`, `neo-json`, `neo-storage`, `neo-crypto`, `neo-consensus`, `neo-core`, `neo-p2p`, `neo-rpc`, `neo-telemetry`, `neo-vm`) to validate cross-layer contracts. A second package, `benches-package/` (`neo-benches`), is independent of the test crate and uses Criterion with `harness = false` to define three named benches — `payload_serialization` (block_processing.rs), `hashing` (state_root.rs), and `vm_execution` — measuring header/transaction serialization, hashing, and VM execution in isolation. Both packages depend on the workspace via `{ workspace = true }` and do not publish.
