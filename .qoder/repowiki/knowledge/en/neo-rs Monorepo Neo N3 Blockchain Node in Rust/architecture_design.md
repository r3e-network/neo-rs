The repository is a Cargo workspace (resolver 2) that enforces a strict bottom-up dependency hierarchy: foundation crates (`neo-primitives`, `neo-config`, `neo-crypto`, `neo-storage`, `neo-io`, `neo-json`) have no intra-workspace dependencies; the core layer (`neo-vm`, `neo-core`, `neo-p2p`, `neo-consensus`) builds on them; the services layer (`neo-rpc`, `neo-telemetry`, `neo-tee`, `neo-hsm`) sits above core; and `neo-node` is the sole application binary that wires all layers together. Cross-crate contracts are defined via traits in `neo-storage` (pluggable store provider/factory), `neo-io`/`neo-json` (serialization boundaries matching C# Neo.IO/Neo.Json), and `neo-p2p` (wire-format message types). Optional capabilities (`neo-tee`, `neo-hsm`) are feature-gated through `neo-node`'s `--features tee|hsm`. The workspace centralises shared dependencies, versions, and profiles (release LTO+strip, production profile) in `Cargo.toml`, while per-network TOML presets (`neo_mainnet_node.toml`, `neo_testnet_node.toml`, `neo_production_node.toml`) drive runtime behaviour. Integration tests (`tests`), benchmarks (`benches-package`), fuzz targets (`fuzz`), and differential verification scripts (`scripts_and_tools`) exercise the same crate boundaries to maintain byte-for-byte compatibility with the C# Neo v3.10.1 reference.
