The crate is a flat collection of single-file modules re-exported from `src/lib.rs`, organized around three concerns: (1) fixed-width numeric primitives (`uint160.rs`, `uint256.rs`) generated by the `uint_type!` macro in `macros.rs`, which emits struct definitions, byte/parse/format methods, `Ord`/`FromStr`/`Display`/`Debug`, and optional `AsRef<[u8; N]>`; (2) protocol enums generated via `protocol_enum!`, `protocol_enum_repr!`, and `protocol_enum_with_unknown!` macros that produce `#[repr(u8)]` enums with `to_byte`/`from_byte`/`as_str`/serde round-trips; (3) domain-specific small types for Neo's P2P/blockchain surface (`inventory_type`, `transaction_attribute_type`, `trigger_type`, `witness_*`, `oracle_response_code`, etc.). The `blockchain/` sub-module defines trait boundaries (`BlockchainProvider`, `PeerRegistry`, `BlockLike`, `HeaderLike`, `TransactionLike`, `NetworkMessage`) used to break circular dependencies between higher-level crates. A strict dependency rule is enforced by Cargo.toml: there are zero `neo-*` dependencies — serialization for UInt160/UInt256 lives in `neo-io::serializable::primitives`. Tests use `proptest` property-based testing with persisted regressions under `proptest-regressions/`.
