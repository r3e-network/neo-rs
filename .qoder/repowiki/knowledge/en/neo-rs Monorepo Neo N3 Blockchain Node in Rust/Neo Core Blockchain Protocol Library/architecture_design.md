The crate is organized as a Layer 1 (Core) library that depends only on foundation crates (`neo-primitives`, `neo-crypto`, `neo-storage`, `neo-io`, `neo-json`) and re-exports them for consumers. The public surface in `src/lib.rs` groups functionality into C#-equivalent namespaces: `ledger` (blocks, transactions, memory pool), `smart_contract` (application engine, native contracts, manifest, iterators), `network::p2p` (framed TCP transport, payloads, local/remote node actors, task manager), `persistence` (storage providers, data cache, RocksDB backend), `wallets` (BIP32/BIP39, NEP6), `state_service` (world state root verification), plus optional feature-gated modules `actors`, `neo_system`, `oracle_service`, `tokens_tracker`, `monitoring`, and `application_logs`. Optional features (`runtime`, `rocksdb`, `upnp`, `monitoring`, `oracle`, `neofs-grpc`, `parallel`) gate entire subsystems via `#[cfg(feature = ...)]` in `lib.rs`. The `neo_system` module provides the `NeoSystem` orchestrator built through a fluent `NeoSystemBuilder`, wiring actors, services, registry, relay, mempool, and persistence. The P2P layer uses tokio with a custom framed codec and separates concerns into `local_node`, `remote_node`, `task_manager`, and `payloads`. Smart contract execution centers on `ApplicationEngine` with native contracts under `smart_contract/native/*` (NEO, GAS, Ledger, Oracle, Policy, Token Management, etc.). Proto definitions for NeoFS gRPC live under `proto/neofs/` and are generated at build time by `build.rs` when the `neofs-grpc` feature is enabled.
