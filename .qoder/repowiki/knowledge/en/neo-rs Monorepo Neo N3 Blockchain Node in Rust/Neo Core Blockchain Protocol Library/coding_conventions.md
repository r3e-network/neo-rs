- Subsystem modules are gated behind Cargo features with `#[cfg(feature = "...")]` attributes on both module declarations and their re-exports in `lib.rs` (e.g., `runtime`, `monitoring`, `oracle`, `neofs-grpc`).
- Public API surface is curated through `pub use` re-exports at the top-level `lib.rs`, grouping types from submodules like `builders`, `network::p2p::payloads`, `smart_contract`, and `wallets` into a flat namespace.
- Module structure mirrors the C# Neo project layout, with Rust modules named after C# namespaces (`ledger`, `smart_contract`, `network`, `persistence`, `wallets`, `events`, `extensions`) and documented as such in doc comments.
- Optional dependencies are declared as `dep:` feature flags in `Cargo.toml` and conditionally compiled via `#[cfg(feature = ...)]` rather than unconditionally linking heavy crates like `reqwest`, `tonic`, `prometheus`, or `rocksdb`.
- Actor-based components follow a consistent pattern of `actor.rs` + `handle.rs` + `mod.rs` + `tests.rs` pairs within each actor subsystem (e.g., `local_node`, `task_manager`, `actors`), separating message handling, lifecycle, and external handles.
- Native contracts under `smart_contract/native/*` share a common structure of `metadata.rs`, `native_impl.rs`, and feature-specific modules (e.g., `governance.rs`, `nep17.rs`, `deposit.rs`), exposing themselves through shared macros and helper traits.
