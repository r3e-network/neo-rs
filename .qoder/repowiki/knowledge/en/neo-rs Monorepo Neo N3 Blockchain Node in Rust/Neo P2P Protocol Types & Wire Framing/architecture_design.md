The crate is a thin, dependency-minimal Layer 1 core that exposes only protocol primitives (no TCP/actor runtime). `lib.rs` re-exports top-level enums (`MessageCommand`, `InventoryType`, `VerifyResult`, `NodeCapabilityType`, etc.) and delegates most enum definitions to the `neo_primitives::p2p_message_command!` macro in `message_command.rs`, which also generates compression whitelists and single-queue/high-priority command sets. `message.rs` implements the wire format: a `RawMessage` with flags/command/varint-length framing plus optional LZ4 compression, serializing/deserializing via `neo_io`. The `payloads/` subdirectory holds per-command payload structs (version, addr, ping, inv, filter_add/load, get_blocks, get_block_by_index, node_capability, network_address_with_time) that depend only on `neo-io` and `neo-primitives`. `traits.rs` defines the implementation boundary — `PeerManager`, `Broadcaster`, `DataRequester`, `P2PService`, `P2PEventSubscriber`, `PeerInfo`, and `P2PConfig` — so concrete async runtimes (tokio, async-std) can be plugged in by consumers like `neo-core`. Error handling is centralized in `error.rs` using `thiserror`, with a uniform `P2PResult<T>` alias. The crate intentionally has no features beyond optional `serde` and depends only on `neo-primitives`, `neo-crypto`, `neo-io`, `tokio`, `async-trait`, `futures`, `rand`, `tracing`, and `serde`.
