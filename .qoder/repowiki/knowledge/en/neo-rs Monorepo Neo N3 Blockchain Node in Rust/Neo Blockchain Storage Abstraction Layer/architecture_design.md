The crate is organized into four top-level modules re-exported from `lib.rs`: `types` (domain primitives `StorageKey`, `StorageItem`, `SeekDirection`, `TrackState`), `cache` (in-memory `DataCache`/`ClonedCache` with `Trackable` entry state tracking), `persistence` (trait layer + concrete implementations), and helpers (`error`, `hash_utils`, `key_builder`).

Inside `persistence`, the trait hierarchy forms the core boundary: `ReadOnlyStoreGeneric<TKey,TValue>` defines read semantics (`try_get`, `contains`, `find` with `SeekDirection`); `WriteStore<TKey,TValue>` adds mutation (`put`, `delete`, default `put_sync`); `Store` composes both plus snapshot lifecycle (`snapshot`, `on_new_snapshot`, `enable_fast_sync_mode`, `flush`, `as_any`). A generic `ReadOnlyStore` alias pins keys/values to `StorageKey`/`StorageItem`. Snapshots are exposed via `StoreSnapshot` and `read_only_store::ReadOnlyStoreGeneric`.

Concrete backends live under `persistence/providers` (`MemoryStore`, `MemorySnapshot`, `MemoryStoreProvider`) implementing the traits. Store creation is decoupled through `StoreProvider` (named factory) and a global `StoreFactory` registry backed by a `LazyLock<RwLock<HashMap<String, Arc<dyn StoreProvider>>>>` that auto-registers an in-memory provider under both its name and the empty-string default. Additional persistence submodules provide layered caching (`data_cache`, `read_cache` with bloom filter and prefetch), transaction support (`transaction::StoreTransaction`), indexing (`index`), and a `StoreCache` wrapper.

Dependency direction is strictly inward: `cache` and `persistence` depend on `types`; `persistence` depends only on `types` and `error`; no module imports the other at the same level except via `lib.rs` re-exports. The crate exposes only trait surfaces and public data types, keeping actual storage engines swappable behind `StoreProvider`.
