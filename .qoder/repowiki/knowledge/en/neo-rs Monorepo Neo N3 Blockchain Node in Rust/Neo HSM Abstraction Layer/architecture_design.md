The crate exposes a single `HsmSigner` trait (in `src/signer/hsm_signer.rs`) that all backends implement: `unlock`, `lock`, `list_keys`, `get_key`, `sign`, `get_public_key`, and `verify_device`. Three optional backend modules are gated by Cargo features — `ledger` (USB HID via `hidapi`), `pkcs11` (via `cryptoki`), and `simulation` (default feature) — each re-exporting its concrete signer through the module's `mod.rs`. A shared `device` module defines `HsmDeviceInfo`/`HsmDeviceType`, while `config.rs` provides an `HsmConfig` builder with per-backend constructors (`ledger`, `pkcs11`, `simulation`). Cross-cutting concerns are isolated in `pin/prompt.rs` (interactive PIN entry with retry) and `error.rs` (a `thiserror`-based `HsmError` enum covering device, PIN, crypto, and feature-gate errors). Public surface is curated in `lib.rs`, which conditionally re-exports only the enabled backends. Crypto helpers for Neo's signature redeem script and public-key normalization live alongside the trait so all signers share identical script-hash derivation.
