The crate is organized as a set of feature-gated sub-modules exposed from `lib.rs`: `enclave` (runtime state machine, sealing/unsealing via HKDF+AES-GCM, monotonic counter persistence), `wallet` (sealed key storage and signing over secp256r1 keys), `mempool` (fair-ordering policy with Merkle-rooted ordering proofs), and `attestation` (DCAP-style quote/report types plus an `AttestationService`). The `sgx` module is compiled only under the `sgx-hw` feature and supplies hardware evidence verification; without it, the `simulation` feature (default) provides deterministic software fallbacks. All modules depend on `enclave` for the shared `TeeEnclave` which owns the sealed sealing key and monotonic counter; `wallet` and `mempool` hold `Arc<TeeEnclave>` to access it. Cross-cutting concerns are centralized in `error.rs` (`TeeError`, `TeeResult`, `EnclaveInitError`) and `fs_acl.rs` (owner-only file/dir permissions). Feature flags gate behavior: `simulation` enables software key derivation and skips SGX calls, `sgx-hw` enables real-quote verification, and `attestation` depends on `sgx-hw`.
